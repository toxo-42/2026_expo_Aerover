> **상태: 판 재구성 (2026-09-29).** 6cm 마커 10개를 자로 대칭 자리에 다시 붙이고 배치를 쟀다 (`markers_W.json` = 220336).
> 5cm 실물 시험은 불합격. 다음은 400~500장 ODM → `to_W.json` → 라벨링 ("남은 일" 10 · 11).

## 왜 필요한가

요구조자를 **3D 맵 위 제자리에** 찍으려면 서로 다른 두 좌표계를 이어야 한다.

| | 좌표계 | 문제 |
|---|---|---|
| A. 3D 맵 (ODM 결과) | 회차마다 임의 | 원점 · 축척 · **어느 쪽이 위인지까지** 매번 다르다 (9/6 회차는 바닥이 44.4° 기울었다) |
| B. 실시간 드론 카메라 | 카메라 기준 | 드론이 돌면 기준도 같이 돈다 |

ArUco 마커를 판에 고정하고 그 배치를 재 두면(`marker_map.py`) 마커들이 **시연 환경만의 고정 좌표계 W (미터)** 가 된다.

```
A → W   3D 맵에 찍힌 마커를 삼각측량 → 배치표와 Umeyama 유사변환 → 메시를 W 로 옮긴다   (align_model.py, 완성)
B → W   실시간 영상에서 같은 마커를 검출 → solvePnP → 드론 카메라 자세 (W 기준)          (pose.py, 완성)
탐지    YOLO 박스 픽셀 → 광선 → W 로 옮긴 메시와 교차 → 요구조자 (x, y, z)              (backproject.py, 완성)
```

A 와 B 가 같은 W 로 모이니 탐지 결과가 맵 위 제자리에 찍힌다.
부수 효과로 **배경 제거가 자동화**된다 — W 에서는 판이 늘 `0~1.22m × 0~1.22m` 라 자르는 상자를 상수로 박을 수 있다.

### 광선을 바닥이 아니라 메시와 교차시켜야 하는 이유

요구조자가 바닥에만 있지 않다 (`environment_img/` 사진). 건물 2~3층 안, 옥상, 잔해 더미 위에도 있다.
바닥 평면(Z=0)과 교차시키면 이들은 전부 엉뚱한 자리에 찍힌다. 그래서 A → W 정합이 필수다.

## 마커 배치 — 모서리 4 + 변 중앙 4 (결정)

**한 화면에 보이는 범위보다 판이 크다.** 드론이 판 중심을 조준해도 판의 네 꼭짓점이
모두 들어오지는 않는다 (핀홀 기준 가까운 쪽 꼭짓점이 화면 밖). 그래서 매 프레임 solvePnP 가
2개 이상 보려면 마커 수가 필요하다.

원궤도 360프레임 가시성 시뮬레이션 (마커 10cm, 검출 한계 40px · 기울기 65°, 왜곡 무시 = 보수적):

| 배치 | 최소 | 평균 | 2개 미만 프레임 |
|---|---:|---:|---:|
| 모서리 4 | 1 | 1.6 | **43%** |
| **모서리 4 + 변 중앙 4** | **4** | **5.0** | **0%** |

마커 화면 크기: 가까운 쪽 약 115px, 먼 쪽 약 73px (정면 환산). 10cm 로 충분하다.
좌표표 · ID 배정은 `ArUco_준비작업.md` 3~4절.

### 마커 크기 — **6cm 확정 (2026-09-22, 09-29 5cm 실물 시험으로 재확인)**

**5cm 는 불합격 (2026-09-29).** 같은 판 · 같은 자리에서 바꿔 찍으니 2개 미만 장 10% → 24~25%, 자세 실패 2~3배,
대상 좌표 95% 22 → 48~57mm. 5cm 회차가 오히려 선명해서 같은 px 에서는 더 잘 잡혔지만 **25px 미만으로 찍히는 마커가
37% → 59~62%** 로 늘어난 것이 원인이다 — 촬영 탓이 아니라 크기 탓. 표 · 근거는 `ArUco_준비작업.md` 2절.

| 손 촬영 한 바퀴 → `size_check` | 10cm (225043) | **6cm (232357)** |
|---|---|---|
| 프레임당 마커 · 2개 미만 · 자세 실패 | 3.7 · 0% · 0장 | 3.5 · 0% · 0장 |
| 대상 좌표 (마커 하나 빼고 역투영) 중앙 / 95% | 12 / 36 mm | **6 / 27 mm** |

10cm 쪽이 나빴던 것은 크기가 아니라 **배치표가 낡아서**다 (판을 다시 꾸미며 마커 0 이 13mm 밀림).
(09-22 기록) 6cm 배치 = 회차 233832 (가까이 60장, 코너 재투영 0.66px, 축척 0↔2 줄자 1.12m) — 지금은 `markers_W_60mm_233832.json`.
10cm 배치는 `markers_W_100mm.json`. 3D 맵 = `3D_model/20260922_234609` (to_W 잔차 중앙 2.2 / 최대 5.2mm, 마커 0 은 ODM 사진 부족으로 빠짐).

**배치 측정(marker_map) 사진 규칙 — 이번에 배운 것:**
- **가까이** — 마커가 화면에서 50px 이상. 판 전체를 한 장에 넣으려고 멀리 찍은 233051(38px)은 재투영 3.9px 로 쓸 수 없었다
- **모든 마커 10장 이상**, 모서리 마커가 특히 빠지기 쉽다
- 축척은 **줄자로** (`--ref 0 2 <m>`). 사진만의 축척은 마커가 작을수록 크게 틀린다 (10cm +3.6%, 6cm +7.8% — 코너가 1~1.5px 안쪽으로 잡히는 만큼).
  09-29 판도 인쇄 한 변 60mm 확인인데 사진 축척이 매번 -6 ~ -7.5% 보정됐다 (0↔2 사진 1.23m → 줄자 1.157m)
- 한 장에 마커 3개 이상, **판을 가로지르는 사선 샷**을 섞는다 — 2개짜리 장으로만 이으면 초기값이 갇힌다 (09-29)
- 마커를 다시 붙였으면 `--init markers_W.json` 으로 이전 배치에서 출발한다 (아래 "marker_map.py 를 만들며 알게 된 것")

아래는 크기를 정하기 전의 기록.

#### (기록) 10cm 로 시작해 실물로 줄여간다

10cm 는 디오라마에 비해 크다. **실물 10cm 로 전체 흐름을 먼저 확인하고, 8 → 6 → 5cm 로 줄여가며 최소 크기를 찾는다.**
크기를 바꿀 때마다 `make_markers.py --size <mm>` 로 뽑고, `markers_W.json` 의 `size_m` 을 인쇄 실측값으로 바꾼다.
판정은 한 바퀴 수집본에 **`size_check.py <폴더> --model <맵회차>`** — 촬영 조건 · 자세 · 대상 좌표 · 배치/정합을 한 번에 낸다.
**"2개 미만" 이 0% 에서 벗어나거나 대상 좌표 95% 가 크게 뛰기 시작하는 크기가 한계**다.

**갠트리가 없을 때 (2026-09-22 기준 제작 중)** — 손으로 들고 돌면 높이가 0.8m 로 낮아지고 흔들린다.
크기 비교는 조건이 같아야 하니 **삼각대(또는 막대)를 판 윗면 위 1.1m · 45° 아래로 고정하고, 바닥에 테이프로
표시한 12곳(판 중심에서 수평 1.05m 원, 30° 간격)에 옮겨 가며 멈춰서 찍는다.** 크기마다 같은 12곳.
자세는 매 장 마커로 새로 풀기 때문에 궤도 자체는 계산에 안 들어간다 — 손 촬영의 손해는 흐림과 시야(낮으면 먼 마커가 납작해짐)뿐이다.

합성 시뮬레이션 (궤도 24곳, 대상 좌표 = 판 위 점을 역투영한 오차):

| 마커 | 선명 (블러 σ 0.9) | 흐림 (블러 σ 1.8) |
|---|---|---|
| 4cm | 프레임당 최소 5개, 95% 0.3mm | ❌ 최소 1개, 95% 68mm |
| 5cm | 최소 6개, 95% 0.3mm | ⚠ 최소 2개, 95% **17mm** (가끔 크게 튄다) |
| 6cm | 최소 6개, 95% 0.4mm | ✅ 최소 4개, 95% 0.8mm |
| 8cm | 최소 7개, 95% 0.2mm | ✅ 최소 5개, 95% 0.4mm |
| 10cm | 최소 7개, 95% 0.2mm | ✅ 최소 6개, 95% 0.3mm |

**실제 드론 카메라의 블러는 σ ≈ 1.7px** (체스보드 경계 2112개의 10~90% 상승 폭, 회차 `204525` 중간 거리.
가까이 찍은 `203642` 는 0.96). 갠트리 거리(1.2~1.9m)에 회전 흔들림까지 더해지면 **흐림 줄이 현실에 가깝다** →
시뮬레이션상 6cm 가 안정권의 경계, 5cm 는 위험. 조명 · 인쇄 · 흔들림은 시뮬레이션에 없으니 실물로 확정한다.

### 추가 마커 2개 — 건물 뒤 구간 보완 (2026-09-23 제안, 09-29 붙임)

> **09-29 판에 8 · 9 를 처음부터 같이 붙였다** (0번에서 15 · 35cm). 단 **건물 배치가 바뀌었다** — 아래 분석은 건물이
> 판 뒤쪽 가장자리에 있던 09-23 판 기준이고, 09-29 판은 건물이 도로 옆 한쪽 변에 선다. 새 ODM 으로 `visibility` 를 다시 돌린다.

건물 두 동을 올린 뒤(3D 맵 `20260923_000331_plus`) 갠트리 궤도를 시뮬레이션하니
**드론이 건물 바로 뒤를 지날 때 마커가 1~2개만 보인다.** 2개로는 자세가 불안하고 1개면 못 푼다.

| 도구 | `aerover/tools/visibility.py` — 궤도(반지름 1.055m · 높이 1.114m · 판 중심 조준)에 가상 카메라를 돌려 마커마다 화면 안 · 25px 이상 · 기울기 70° 이하 · **메시에 안 가림** 을 센다 |
|---|---|

```bash
cd apps/aerover
uv run python -m tools.visibility 3D_model/20260923_000331_plus --suggest --need 3
```

**지금 (마커 8개)** — 평균 4.1개 (건물이 없다면 5.0). 약한 구간은 궤도 **70~110°**
(0° = 판 중심에서 +X 쪽, 90° = +Y 쪽 = **판 뒤쪽, 건물 두 동 바로 뒤**):

| 궤도 | 보이는 마커 |
|---|---|
| 70~75°, 90~110° | 2개 |
| **80~88°** | **1개** — 자세를 못 푼다 |

건물 위치 (W): 왼쪽 동 x 0.18~0.52 · 오른쪽 동 x 0.78~1.12, 둘 다 y 1.00~1.25 (판 뒤쪽 가장자리).
뒤에서 보면 판 대부분이 건물에 가리고, **왼쪽 동의 왼편(x < 0.18) 틈으로 판 왼쪽 가장자리 앞부분만** 보인다.
그래서 추천 자리가 전부 판 왼쪽 가장자리다.

**붙일 자리 — 둘 다 0번(앞-왼 모서리)과 7번(왼쪽 변 중앙)을 잇는 선 위:**

| 새 ID | W 중심 (x, y) | 실물에서 찾는 법 | 효과 |
|---|---|---|---|
| **8** | (0.07, **0.22**) | 0번 마커 중심에서 7번 쪽으로 **15cm** | 3개 미만 14곳 중 11곳을 메운다 |
| **9** | (0.07, **0.42**) | 0번 마커 중심에서 7번 쪽으로 **35cm** (7번에서 0번 쪽으로 약 19cm) | 남은 3곳(80~88°)을 메운다 |

- **둘 다 붙이면: 궤도 어디서나 최소 3개 · 평균 5.5개**, 2개 미만 0곳 (지금 최소 1 · 평균 4.1)
- 8번 하나만: 최소 2 · 평균 4.7 (80~88° 는 여전히 2개)
- 자리의 판 높이는 +1~4mm (소품 없는 바닥)이다. **방향은 상관없다** — 배치표를 사진으로 잰다
- 비슷한 효과의 대안 자리: 8번 (0.07, 0.27~0.37), 9번 (0.12, 0.37~0.42). 소품이 있으면 이 범위에서 옮긴다
- 이 수치는 **상한**이다 (흐림 · 조명 · 마커 바로 옆 3cm 안 소품의 가림은 안 넣었다). 실물 갠트리에서 `size_check` 로 확인할 것

**붙인 뒤 할 일:**

1. `uv run python make_markers.py --size 60 --ids 10 --out aruco_markers_60mm_8-9.pdf` → ID 8 · 9 쪽만 인쇄 (100% 배율, 흰 여백째)
2. 위에서 **가까이** 내려다본 사진 40~60장 (마커 50px 이상, 모든 마커 10장 이상 — 위 "배치 측정 사진 규칙")
3. `uv run python marker_map.py ../aerover/sessions/<회차> --size 0.06 --ref 0 2 1.12` → `markers_W.json` (10개)
4. `uv run python align_model.py ../aerover/3D_model/20260923_000331_plus` → `to_W.json` 다시 (맵은 그대로 써도 된다 — 새 마커가 맵에 없어도 정합은 나머지 8개로 한다)
5. `tools.visibility` 를 다시 돌려 최소 3 이 나오는지 확인
